# Exported viewer port to supersplat-viewer 1.35 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every fork exported-viewer feature works on supersplat-viewer 1.35.0 (bundled in `@playcanvas/splat-transform` 3.6.4) exactly as it did on 1.31.2.

**Architecture:** One engine patch publishes the internal `Viewer` as `window.__supersplatViewer` at `new Viewer(...)` and calls an optional `window.__ssOnViewer(viewer)` hook, synchronously before the viewer builds its UI. Each companion is then re-anchored to 1.35: `sse-` class selectors, the `selectedAnnotation` selection model (`selectedAnnotation:changed` / `viewer.selectAnnotation(i)`), `state.loaded` readiness, `config.ui`, and brand markup that now lives in `index.js`. A rewritten drift test pins every anchor against the real installed bundle.

**Tech Stack:** TypeScript; companion runtimes are ES5 template-literal strings injected into the exported HTML; Vitest; Rollup.

**Spec:** `docs/superpowers/specs/2026-09-24-viewer-135-port-design.md` (read it first, including its "Amendments from plan research" section).

## Review Focus

- **Handle-patch miss:** a future bundle without `const viewer = new Viewer(global, gsplatLoad, skyboxLoad, collisionLoad);` must fail the export loudly on every path: single-file HTML, package ZIP, streaming ZIP, and the server via dist-shared. Pinned by Task 1's export-core test.
- **Re-selecting the same annotation:** the camera flies with no `selectedAnnotation:changed`. The portal guard and the iframe `activated` message must still fire. Pinned by the Task 4 and Task 5 wrap tests.
- **`?noui`:** `config.ui === false`. iframe goto keeps reporting `unavailable`, portal markers stay non-interactive, and the loading bar stands down. Pinned in Tasks 4, 5 and 7.
- **Brand name containing `$`, `"` or `\`:** it must reach `index.js`'s `uiHtml` string without breaking the JS literal or triggering a `$` substitution. Pinned in Task 8.
- **Annotation text written before i18n translates it:** the hook must run before `initUI` copies title/text. That is structural: the patch fires inside `createViewer`, which has no await between `new Viewer` and `initUI`. The drift test in Task 9 pins that no await sits between them.
